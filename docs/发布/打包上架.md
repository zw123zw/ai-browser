# 打包上架指南

> 本文档详细说明 AI Browser 扩展的打包流程、激活码生成流程、Chrome Web Store 上架流程。

---

## 1. 环境准备

### 1.1 Rust 工具链

```bash
# 安装 Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# 添加 wasm32 编译目标
rustup target add wasm32-unknown-unknown

# 安装 wasm-pack
cargo install wasm-pack

# 验证
rustc --version
wasm-pack --version
```

### 1.2 Node.js 依赖

```bash
# 安装 javascript-obfuscator（开发依赖）
npm install javascript-obfuscator --save-dev

# 安装 ed25519 签名库（激活码生成工具用）
npm install @noble/ed25519 --save-dev
```

### 1.3 Ed25519 密钥对（首次使用前生成）

```bash
# 生成密钥对
node scripts/gen-license.js --generate-keys

# 输出:
#   scripts/keys/ed25519-private.key  ← 私钥（离线保管，绝不公开）
#   scripts/keys/ed25519-public.key   ← 公钥（嵌入 wasm）
#
# 公钥需复制到 wasm-license/src/ 目录供 Rust 编译使用
```

**⚠️ 私钥安全**：
- `scripts/keys/ed25519-private.key` 已在 `.gitignore` 中
- 绝不提交到仓库
- 建议离线保管（U 盘 / 密码管理器）
- 私钥泄露 = 任何人可生成有效激活码

## 2. 打包流程

### 2.1 一键打包命令

```bash
npm run build:store
```

### 2.2 完整流程详解

`scripts/build-store.sh` 执行以下步骤：

```
Step 1: 生成 build_seed
─────────────────────────────────────────
  build_seed = random 32 字节 hex
  写入 .build-seed 文件
  用途：影响 JS 混淆参数 + Wasm 编译常量

Step 2: 递增版本号
─────────────────────────────────────────
  package.json version: 1.8.3 → 1.8.4
  每次构建自动 patch +1

Step 3: 编译 Wasm
─────────────────────────────────────────
  cd wasm-license
  wasm-pack build --target web --release

  build.rs 读取 .build-seed → 编译为 Rust 常量
  产出:
    public/wasm/license.js      ← wasm-bindgen JS 胶水层
    public/wasm/license_bg.wasm ← 二进制（~50-80KB）

Step 4: WXT 构建
─────────────────────────────────────────
  wxt build
  产出: .output/chrome-mv3/ 目录

Step 5: JS 混淆（版本轮转）
─────────────────────────────────────────
  node scripts/obfuscate.js --seed $build_seed

  基于 build_seed 随机微调混淆参数:
    controlFlowFlatteningThreshold: 0.6~0.9
    deadCodeInjectionThreshold: 0.2~0.5
    stringArrayThreshold: 0.6~0.9
    splitStringsChunkLength: 6~13

  混淆目标: background.js, content-scripts/content.js

  Chrome Web Store 兼容配置:
    selfDefending: false        ← 禁止
    debugProtection: false      ← 禁止
    domainLock: []              ← 禁止
    disableConsoleOutput: false ← 建议关闭

Step 6: 打包 zip
─────────────────────────────────────────
  zip -r lingbot-v1.8.4-a1b2c3d4.zip .output/chrome-mv3/
```

### 2.3 构建产物

```
.output/
├── chrome-mv3/                    ← 可直接安装的扩展目录
│   ├── manifest.json
│   ├── background.js              ← 混淆后
│   ├── content-scripts/
│   │   └── content.js             ← 混淆后
│   ├── wasm/
│   │   ├── license.js             ← wasm 胶水层
│   │   └── license_bg.wasm        ← 二进制
│   └── ...
└── lingbot-v1.8.4-a1b2c3d4.zip   ← 上传 Chrome Web Store 的 zip
```

### 2.4 版本轮转验证

```bash
# 连续构建两次
npm run build:store
cp -r .output/chrome-mv3 /tmp/build1
npm run build:store
cp -r .output/chrome-mv3 /tmp/build2

# 对比（应该不同）
diff /tmp/build1/background.js /tmp/build2/background.js
# → 输出不同（混淆参数随机）

diff /tmp/build1/wasm/license_bg.wasm /tmp/build2/wasm/license_bg.wasm
# → 输出不同（build_seed 不同）
```

## 3. 激活码生成流程

### 3.1 生成单个激活码

```bash
# 绑定版本 + 有效期 30 天 + 全功能
node scripts/gen-license.js --version 1.8.4 --days 30 --features voice,automation

# 输出:
# AIB-XK3M-P7N2-R9TQ
```

### 3.2 批量生成激活码

```bash
# 生成 100 个激活码，输出到 licenses.csv
node scripts/gen-license.js \
  --version 1.8.4 \
  --count 100 \
  --days 30 \
  --features voice,automation \
  --output licenses.csv

# licenses.csv 格式:
# code,version,expire,features
# AIB-XK3M-P7N2-R9TQ,1.8.4,2026-07-28,voice|automation
# AIB-L5F8-W2J6-H4Y1,1.8.4,2026-07-28,voice|automation
# ...
```

### 3.3 生成绑定设备的激活码

```bash
# 用户提供设备指纹，生成只能在该设备上使用的激活码
node scripts/gen-license.js \
  --version 1.8.4 \
  --days 30 \
  --fingerprint a1b2c3d4e5f6...

# 输出:
# AIB-XK3M-P7N2-R9TQ（绑定设备 a1b2c3d4...）
```

### 3.4 生成设备变更重置码

```bash
# 用户换设备后，提供旧指纹和新指纹
node scripts/gen-license.js \
  --reset \
  --old-fingerprint abc123... \
  --new-fingerprint def456...

# 输出:
# AIB-RESET-XXXX-XXXX（重置码，用户输入后迁移授权到新设备）
```

### 3.5 激活码技术细节

```
激活码格式: AIB-XXXX-XXXX-XXXX-XXXX

编码结构:
  ┌─────────┬──────────────────────────────────────────┐
  │ 前缀    │ AIB                                      │
  ├─────────┼──────────────────────────────────────────┤
  │ 第 1 组  │ version(1B) + expire_month(1B)           │
  │         │ + features(1B) + random(1B)              │
  ├─────────┼──────────────────────────────────────────┤
  │ 第 2 组  │ expire_ts 低 4 字节 (base32)             │
  ├─────────┼──────────────────────────────────────────┤
  │ 第 3 组  │ fingerprint_hash 低 4 字节               │
  ├─────────┼──────────────────────────────────────────┤
  │ 第 4 组  │ Ed25519 签名前 4 字节                     │
  └─────────┴──────────────────────────────────────────┘

签名数据: version + expire_ts + features + fingerprint_hash
签名算法: Ed25519（私钥签名，公钥验证）
```

## 4. Chrome Web Store 上架流程

### 4.1 注册开发者账号

1. 访问 [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole)
2. 使用 Google 账号登录
3. 支付 $5 注册费（一次性）
4. 同意开发者协议

### 4.2 准备上架材料

| 材料 | 规格 | 说明 |
|------|------|------|
| 扩展 zip | `< 100MB` | `lingbot-v1.8.4-a1b2c3d4.zip` |
| 商店图标 | `128x128` PNG | `icon.png` |
| 宣传图 | `1280x800` 或 `640x400` | 至少 1 张，最多 5 张 |
| 小宣传图 | `440x280` | 可选 |
| 产品描述 | 中文 + 英文 | 详细功能介绍 |
| 隐私政策 | URL | 必须提供 |

### 4.3 上传步骤

1. 登录 [Developer Dashboard](https://chrome.google.com/webstore/devconsole)
2. 点击「New Item」
3. 上传 `lingbot-v1.8.4-a1b2c3d4.zip`
4. 填写商品信息：
   - 名称：小灵 - AI 语音浏览器助手
   - 描述：中文 + 英文
   - 类别：Productivity
   - 语言：中文
5. 上传宣传图
6. 填写隐私政策 URL
7. 选择可见性：Public / Unlisted
8. 点击「Publish」

### 4.4 审核周期

| 阶段 | 时间 | 说明 |
|------|------|------|
| 初次提交 | 1-7 天 | 首次审核较慢 |
| 版本更新 | 1-3 天 | 后续更新较快 |
| 被拒 | 需修改后重新提交 | 查看拒绝原因并修复 |

### 4.5 审核注意事项

**必须避免**（会导致审核不通过）：

| 项目 | 原因 |
|------|------|
| `selfDefending: true` | 注入检测代码，审核标记 |
| `debugProtection: true` | 注入 debugger 语句 |
| `domainLock` | 域名锁定 |
| `eval()` | 动态代码执行 |
| 远程代码执行 | 从外部加载并执行 JS |
| 未声明的权限 | manifest 中未声明但使用的权限 |

**可以使用**：

| 项目 | 说明 |
|------|------|
| JS 混淆 | 变量名随机、控制流扁平化、死代码注入 |
| Wasm 二进制 | 需在 manifest 声明 `web_accessible_resources` |
| stringArray + base64 | 字符串加密 |
| transformObjectKeys | 对象键名转换 |

### 4.6 Manifest 声明 Wasm 资源

```json
// wxt.config.ts → manifest.web_accessible_resources
{
  "web_accessible_resources": [
    {
      "resources": ["wasm/*.js", "wasm/*.wasm"],
      "matches": ["<all_urls>"]
    }
  ]
}
```

## 5. 版本更新流程

### 5.1 常规更新（功能更新）

```bash
# 1. 开发功能
# 2. 提交代码
git add . && git commit -m "feat: xxx"

# 3. 打包（自动递增版本号 + 重新混淆 + 重新编译 wasm）
npm run build:store

# 4. 上传到 Chrome Web Store
# → Developer Dashboard → 选择扩展 → Upload new package
# → 上传 .output/lingbot-vX.Y.Z-xxxx.zip

# 5. 等待审核通过
```

### 5.2 紧急修复

```bash
# 1. 修复 bug
# 2. 打包
npm run build:store

# 3. 上传（审核周期 1-3 天）
```

### 5.3 旧版本激活码兼容

```
版本轮转后，旧版本激活码在新版本上验证失败。

解决方案:
  1. 生成激活码时支持多版本:
     node gen-license.js --version 1.8.3,1.8.4,1.8.5 --days 30

  2. 或者给用户发新版本激活码（推荐）
```

## 6. 销售渠道配置

### 6.1 Gumroad（海外）

1. 注册 [Gumroad](https://gumroad.com/) 账号
2. 创建数字产品
3. 设置价格（如 $9.99/月）
4. 配置自动发码：
   - 上传 `licenses.csv` 到 Gumroad 的「Keys」功能
   - 用户付款后自动从 CSV 中取一个码发到邮箱
5. 分享产品链接

### 6.2 爱发电（国内）

1. 注册 [爱发电](https://afdian.net/) 账号
2. 创建发电方案
3. 配置自动回复（含激活码）
4. 或使用 API 对接自动发码系统

### 6.3 手动分发

适用于早期用户、内测用户：

```bash
# 为特定用户生成激活码
node scripts/gen-license.js \
  --version 1.8.4 \
  --days 30 \
  --features voice,automation \
  --comment "用户张三"

# 手动发送激活码（微信/邮件）
```

## 7. 故障排查

### 7.1 Wasm 编译失败

```bash
# 检查 Rust 工具链
rustc --version
wasm-pack --version
rustup target list --installed  # 应包含 wasm32-unknown-unknown

# 清理重编译
cd wasm-license
cargo clean
wasm-pack build --target web --release
```

### 7.2 混淆后扩展异常

```bash
# 跳过混淆测试
wxt build
# 直接加载 .output/chrome-mv3 测试

# 如果正常 → 混淆配置问题
# 检查 scripts/obfuscate.js 中的选项
```

### 7.3 激活码验证失败

```
可能原因:
  1. 版本不匹配 → 激活码绑定的版本与当前扩展版本不同
  2. 设备不匹配 → 激活码绑定的 fingerprint 与当前设备不同
  3. 已过期 → expire_ts 已过
  4. 私钥不匹配 → 生成码的私钥与 wasm 中的公钥不是一对

排查步骤:
  1. 检查扩展版本: Settings → 关于
  2. 检查设备指纹: Settings → License → 设备信息
  3. 检查激活码有效期
  4. 重新生成密钥对 + 重新编译 wasm
```

### 7.4 Chrome Web Store 审核被拒

```
常见拒绝原因及修复:

1. "Contains code that isn't obfuscated"
   → 检查是否所有 JS 都经过混淆

2. "Uses eval or similar dynamic code execution"
   → 关闭 javascript-obfuscator 的 selfDefending 等选项

3. "Remote code execution"
   → 确保没有从外部加载并执行 JS（读 JSON 数据可以）

4. "Permissions not justified"
   → 确保 manifest 中的权限都有合理用途

5. "Privacy policy missing"
   → 提供隐私政策 URL
```
