# 打包指南

> 扩展的完整打包流程：环境准备 → WASM 编译 → WXT 构建 → JS 混淆 → 打包 zip → 激活码生成。

---

## 1. 环境准备

### 1.1 Rust 工具链

```bash
# 安装 Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# 添加 wasm32 编译目标
rustup target add wasm32-unknown-unknown

# 安装 wasm-pack
cargo install wasm-pack

# 验证
rustc --version
wasm-pack --version
```

### 1.2 Node.js 依赖

```bash
# 混淆工具
npm install javascript-obfuscator --save-dev

# 激活码生成工具
npm install @noble/ed25519 --save-dev
```

### 1.3 Ed25519 密钥对（首次使用前生成）

```bash
node scripts/gen-license.js --generate-keys
```

输出：

| 文件 | 用途 | 安全要求 |
|------|------|----------|
| `scripts/keys/ed25519-private.key` | 签名激活码 | **离线保管，绝不公开，不提交仓库** |
| `scripts/keys/ed25519-public.key` | 嵌入 wasm 验证 | 复制到 `wasm-license/src/` 供编译 |

> ⚠️ 私钥泄露 = 任何人可生成有效激活码。建议存 U 盘或密码管理器。

## 2. 一键打包

```bash
npm run build:store
```

### 2.1 执行流程

```
[1/6] 生成 build_seed
  └─ openssl rand -hex 32 → 写入 .build-seed
  └─ 用途：影响 JS 混淆参数 + Wasm 编译常量（版本轮转）

[2/6] 递增版本号
  └─ package.json version: 1.8.16 → 1.8.17（patch +1）

[3/6] 编译 Wasm
  └─ cd wasm-license && wasm-pack build --target web --release --no-opt
  └─ build.rs 读取 .build-seed → 编译为 Rust 常量
  └─ 产出: public/wasm/license.js + license_bg.wasm (~150KB)

[4/6] WXT 构建
  └─ wxt build → .output/chrome-mv3/

[5/6] JS 混淆（版本轮转）
  └─ node scripts/obfuscate.js --seed $build_seed
  └─ 基于 seed 随机微调混淆参数，每次构建产物不同

[6/6] 打包 zip
  └─ zip -r lingbot-v1.8.17-a1b2c3d4.zip .
```

### 2.2 构建产物

```
.output-store/
├── lingbot-v1.8.17-20260701-143022-a1b2c3d4/   ← 可直接安装的扩展目录
│   ├── manifest.json
│   ├── background.js              ← 混淆后
│   ├── content-scripts/
│   │   └── content.js             ← 混淆后
│   ├── wasm/
│   │   ├── license.js             ← wasm 胶水层
│   │   └── license_bg.wasm        ← 二进制
│   └── ...
└── lingbot-v1.8.17-a1b2c3d4.zip   ← 上传用的 zip
```

### 2.3 JS 混淆策略

| 文件大小 | 模式 | controlFlowFlattening | deadCodeInjection | 说明 |
|----------|------|----------------------|-------------------|------|
| ≤ 1MB | full | 0.6 ~ 0.9 | 开启 (0.2~0.5) | 全量混淆 |
| > 1MB | light | 0.3 ~ 0.5 | 关闭 | 避免体积膨胀 |

Chrome Web Store 兼容约束（必须遵守）：

| 选项 | 必须为 | 原因 |
|------|--------|------|
| `selfDefending` | `false` | 注入检测代码，审核不通过 |
| `debugProtection` | `false` | 注入 debugger 语句 |
| `domainLock` | `[]` | 域名锁定 |
| `eval()` | 不使用 | 动态代码执行 |

### 2.4 版本轮转验证

```bash
# 连续构建两次，对比产物应该不同
npm run build:store
cp -r .output-store/lingbot-v* /tmp/build1
npm run build:store
cp -r .output-store/lingbot-v* /tmp/build2

diff /tmp/build1/background.js /tmp/build2/background.js       # 不同 ✓
diff /tmp/build1/wasm/license_bg.wasm /tmp/build2/wasm/license_bg.wasm  # 不同 ✓
```

## 3. 激活码生成

### 3.1 单个激活码

```bash
node scripts/gen-license.js --version 1.8.17 --days 30
# 输出: AIB-XK3M-P7N2-R9TQ-W3J6
```

### 3.2 批量生成

```bash
node scripts/gen-license.js \
  --version 1.8.17 \
  --count 100 \
  --days 30 \
  --output licenses.csv
```

`licenses.csv` 格式：

```csv
code,version,expire
AIB-XK3M-P7N2-R9TQ-W3J6,1.8.17,2026-07-31
AIB-L5F8-W2J6-H4Y1-K9P3,1.8.17,2026-07-31
```

### 3.3 绑定设备的激活码

```bash
# 用户提供设备指纹，生成只能在该设备上使用的激活码
node scripts/gen-license.js \
  --version 1.8.17 \
  --days 30 \
  --fingerprint a1b2c3d4e5f6...
```

### 3.4 设备变更重置码

```bash
# 用户换设备后，提供旧指纹和新指纹
node scripts/gen-license.js \
  --reset \
  --old-fingerprint abc123... \
  --new-fingerprint def456...
# 输出: AIB-RESET-XXXX-XXXX
```

### 3.5 多版本兼容

```bash
# 一个激活码兼容多个版本（版本轮转过渡期用）
node scripts/gen-license.js --version 1.8.16,1.8.17,1.8.18 --days 30
```

### 3.6 激活码结构

```
格式: AIB-XXXX-XXXX-XXXX-XXXX

┌─────────┬──────────────────────────────────────────┐
│ 前缀    │ AIB                                      │
├─────────┼──────────────────────────────────────────┤
│ 第 1 组  │ version(1B) + expire_month(1B)           │
│         │ + features(1B) + random(1B)              │
├─────────┼──────────────────────────────────────────┤
│ 第 2 组  │ expire_ts 低 4 字节 (base32)             │
├─────────┼──────────────────────────────────────────┤
│ 第 3 组  │ fingerprint_hash 低 4 字节               │
├─────────┼──────────────────────────────────────────┤
│ 第 4 组  │ Ed25519 签名前 4 字节                     │
└─────────┴──────────────────────────────────────────┘

签名数据: version + expire_ts + features + fingerprint_hash
签名算法: Ed25519（私钥签名，公钥验证）
验证位置: wasm-license/src/license.rs（wasm 内验证，不暴露逻辑）
```

## 4. 收款与自动发码

### 4.1 Gumroad（海外，推荐）

1. 注册 [Gumroad](https://gumroad.com/) 账号
2. 创建数字产品，设置价格（如 $9.99/月）
3. 上传 `licenses.csv` 到 Gumroad 的「Keys」功能
4. 用户付款后自动从 CSV 取一个码发到邮箱

### 4.2 爱发电（国内）

1. 注册 [爱发电](https://afdian.net/) 账号
2. 创建发电方案
3. 配置自动回复（含激活码）或使用 API 对接自动发码

### 4.3 手动分发（早期用户/内测）

```bash
# 为特定用户生成
node scripts/gen-license.js --version 1.8.17 --days 30 --comment "用户张三"
# 手动通过微信/邮件发送
```

## 5. 故障排查

### 5.1 Wasm 编译失败

```bash
rustc --version
wasm-pack --version
rustup target list --installed  # 应包含 wasm32-unknown-unknown

# 清理重编译
cd wasm-license && cargo clean
wasm-pack build --target web --release --no-opt
```

### 5.2 混淆后扩展异常

```bash
# 跳过混淆直接测试
wxt build
# 加载 .output/chrome-mv3 测试
# 正常 → 混淆配置问题，检查 scripts/obfuscate.js
```

### 5.3 激活码验证失败

| 可能原因 | 排查方式 |
|----------|----------|
| 版本不匹配 | Settings → 关于，检查扩展版本 |
| 设备不匹配 | Settings → License → 设备信息，检查 fingerprint |
| 已过期 | 检查激活码有效期 |
| 私钥不匹配 | 重新生成密钥对 + 重新编译 wasm |
