# 打包与激活码指南

## 命令总览

| 命令 | 输出 | 用途 |
|------|------|------|
| `npm run build` | `.output/release-v{版本}-{时间}-{seed}/` | 构建（test + prod） |
| `npm run build:test` | 同上 | 仅构建 test |
| `npm run build:prod` | 同上 | 仅构建 prod |
| `npm run gen-license -- --count=100 --days=30` | `licenses-v{版本}.csv` | 生成激活码 |

**自定义参数：**

```bash
# 自定义试用期（5天）和激活期（30天）
npm run build -- --trial-days=5 --activation-days=30

# 自定义激活码有效期和数量
npm run gen-license -- --count=50 --days=60

# 为旧 release 生成激活码
npm run gen-license -- --release=.output/release-v2.0.2-... --count=100 --days=30
```

## 1. 环境准备

### 1.1 Rust 工具链

```bash
# 安装 Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# 添加 wasm32 编译目标
rustup target add wasm32-unknown-unknown

# 安装 wasm-pack
cargo install wasm-pack

# 验证
rustc --version
wasm-pack --version
```

### 1.2 Ed25519 密钥对

首次打包时自动生成，也可手动生成：

```bash
node scripts/gen-license.js --generate-keys
```

| 文件 | 用途 | 安全要求 |
|------|------|----------|
| `scripts/keys/ed25519-private.key` | 签名激活码 | **离线保管，绝不公开，不提交仓库** |
| `scripts/keys/ed25519-public.key` | 嵌入 Wasm 验证 | 随扩展分发给用户 |

> ⚠️ 私钥泄露 = 任何人可生成有效激活码。

## 3. 生产包（上架用）

```bash
npm run build:prod
```

输出：`.output/lingbot-v2.0.2-20260702-185849-67aa5519.zip`

- 无日志
- Wasm 编译 + esbuild 压缩
- 可直接上传 Chrome Web Store

### 内部流程

```
[1/7] 生成 BUILD_SEED（随机 32 字节）
[2/7] 读取 package.json 版本号
[3/7] 编译 Wasm（Rust → wasm，~150KB）
[4/7] 构建扩展（WXT + Vue）
[5/7] JS 压缩（esbuild minify）
[6/7] 打包 zip
[7/7] 清理构建目录
```

### Chrome Web Store 审核要点

| 允许 | 禁止 |
|------|------|
| esbuild 压缩 + mangle | javascript-obfuscator |
| Wasm 二进制 | eval() |
| 字符串压缩 | selfDefending / debugProtection |

## 4. 激活码系统

### 4.1 绑定关系

激活码绑定两个值：

| 绑定项 | 说明 | 影响 |
|--------|------|------|
| **版本号** | package.json 的 version | 同版本可通用 |
| **BUILD_SEED** | 每次 build:prod 生成的随机值 | 不同打包次的码不通用 |

**结论：每次 `build:prod` 后需要重新生成激活码。**

### 4.2 生成激活码

```bash
# 当前版本 + 当前 BUILD_SEED（默认）
npm run gen-license -- --count=100 --days=30

# 指定旧 release 目录（读取该打包的 BUILD_SEED）
npm run gen-license -- --release=.output/release-v2.0.2-20260702-192548-8e883d1e --count=100 --days=30
```

输出：`docs/发布/licenses-v{版本}.csv`

```csv
code,version,expire
AIB-AEEB7IQ-ISHQ2WA-G6UO5QO7B654Y,2.0.2,2026-08-01
AIB-AEEB6GQ-ISHQ2WQ-G6UO5QOXC3OLG,2.0.2,2026-08-01
```

### 4.3 激活码有效期

- `--days=30` → 激活后 30 天有效
- 从**激活当天**开始算，不是从生成当天
- 过期后需要新激活码
- 激活后有效期重置（不叠加）

### 4.4 发码流程

```
1. npm run build:prod          → 打包
2. npm run gen-license -- --count=100 --days=30  → 生成激活码
3. 上传扩展到 Chrome Web Store
4. 上传 licenses-v{版本}.csv 到 Gumroad/爱发电
5. 用户付款 → 自动发码到邮箱
```

### 4.5 旧版本支持

```bash
# 给旧版本用户生成激活码（指定旧 release 目录）
npm run gen-license -- --release=.output/release-v1.8.42-20260701-143022-a1b2c3d4 --count=10 --days=30
# 输出: docs/发布/licenses-v1.8.42.csv
```

## 5. Wasm 安全机制

### 5.1 密钥对

- **私钥**：签名激活码，只在你电脑上，从不发布
- **公钥**：验证激活码，嵌入 Wasm 二进制，随扩展分发

### 5.2 流程

```
你的电脑:
  激活码 + 私钥 → Ed25519 签名 → 签名嵌入激活码

用户浏览器:
  激活码 + 公钥（Wasm 内）→ Ed25519 验证 → 通过/拒绝
```

### 5.3 安全性

- 攻击者提取 Wasm → 拿到公钥 → 只能验证，不能生成新码
- 攻击者要生成码 → 需要私钥 → 私钥不在扩展里，拿不到

## 7. 故障排查

### Wasm 加载失败

检查 manifest.json 是否包含：
```json
{
  "web_accessible_resources": [
    { "resources": ["wasm/*.js", "wasm/*.wasm"], "matches": ["<all_urls>"] }
  ]
}
```

### BigInt 错误

确保传给 Wasm 的时间戳用 `BigInt(Date.now())`，不是 `Date.now()`。

### 激活码无效

1. 检查版本号是否匹配
2. 检查 BUILD_SEED 是否匹配（重新打包后需重新生成码）
3. 检查设备指纹是否匹配（换设备需新码）

### 混淆后扩展异常

```bash
# 跳过混淆直接测试
npx wxt build
# 加载 .output/chrome-mv3 测试
```
